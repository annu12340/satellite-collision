Split-Brain Architecture: Edge + Ground

Satellites can't always wait for ground. We split decision-making: reflexes on the spacecraft, strategy on the ground.

⚡ Edge (NVIDIA Jetson Nano)

  • Local conjunction screening (neighbors)
  • Greedy optimizer (immediate threats)
  • Autonomous maneuver execution (<1s)
  • 10W power, 128-core GPU, $99
  • No ground link required

Data Flow Pipeline

From raw tracking data to actionable decisions in 8 seconds

1
State Initialization

Parse spacecraft TLEs into 6-DOF state vectors [x, y, z, vx, vy, vz] in ECI frame + 6×6 covariance matrices. Module: utils.py

2
Orbit Propagation

Propagate all spacecraft forward 24h using RK7(8) with J2, atmospheric drag, and SRP perturbations. Simultaneously propagate uncertainty via State Transition Matrix. Module: orbital_mechanics.py

3
Conjunction Screening

All-vs-all geometric filtering: apogee/perigee overlap, orbital plane intersection, distance threshold. Reduces O(N²) pairs by ~90%. Module: conjunction.py

4
Probability of Collision

For flagged pairs: compute TCA (time of closest approach), project into encounter B-plane, evaluate Foster's Pc integral over combined covariance ellipsoid. Module: conjunction.py

5
Risk Scoring & Network

Score each conjunction: Pc × consequence (debris potential) × cascade factor. Build risk graph (NetworkX) with spacecraft as nodes, conjunctions as edges. Module: risk_optimizer.py

6
Multi-Strategy Optimization

Run three strategies in parallel: Greedy (highest-risk-first), Network Flow MILP (fuel-optimal allocation), MCTS (7-day lookahead). Compare and select best risk/fuel tradeoff. Module: risk_optimizer.py

7
Maneuver Planning

For each selected conjunction: compute STM at burn time, optimize Δv direction via miss-distance gradient, verify no secondary threats created. Module: avoidance.py

8
Output & Visualization

Publish decisions via REST API + SSE. Render 3D orbits, B-plane geometry, risk timelines, and explainable recommendations to operator dashboard. Module: api.py + app.js

Tech Stack Deep Dive

Purpose-chosen tools for scientific computing, optimization, and real-time visualization

NumPy + SciPy

Scientific Computing

Vectorized orbital state propagation across 10k objects. SciPy's RK7(8) integrator for high-fidelity trajectory prediction. BLAS/LAPACK for covariance matrix operations.

numpy>=1.24 · scipy>=1.10

NetworkX

Graph Optimization

Models the conjunction risk network as a weighted graph. Min-cost max-flow solves the global fuel allocation problem optimally. Connected-components analysis identifies coupled threat clusters.

networkx>=3.0

NVIDIA CuOpt

GPU-Accelerated Solver

Reformulates maneuver sequencing as a Vehicle Routing Problem. GPU-accelerated MILP solves in 1 second what NetworkX takes 5 minutes for at 10k+ scale. Sub-second decision times for production constellations.

cuopt via REST API

OpenAI GPT-4

AI Analysis & Explainability

Translates optimizer outputs into operator-friendly recommendations. Natural language query interface for intervention planning. Never invents physics; it narrates already-solved plans.

openai>=1.0

NVIDIA Jetson Nano

Edge Compute (On-Satellite)

10W power envelope, 128-core Maxwell GPU, 472 GFLOPS on a credit-card-sized board. Runs local greedy optimizer and conjunction screening autonomously when ground link is unavailable.

$99 · 10W · radiation-tolerant

Real-Time 3D Visualization

WebGL rendering of orbital configurations, conjunction geometry, and debris fields. Plotly for interactive 3D scatter plots. No plugins required; runs in any modern browser.

Why Kiro for This Project?

Orbital mechanics code is unforgiving: wrong units, incorrect frame transforms, or sign errors in perturbation models produce subtly wrong results that propagate through the entire system. Kiro's steering files keep the physics reference (docs/physics.md) and coordinate conventions permanently in context, eliminating an entire class of errors.

The spec workflow was essential for the optimizer: the MCTS implementation required careful requirements (what state representation? what reward function? what rollout policy?) before any code was written. Kiro's requirements → design → tasks pipeline prevented premature coding on a problem where the algorithm design matters more than the implementation details.

Hooks automated the tedious parts: every new avoidance strategy automatically validates its interface, every file save checks for common errors, and every session ends with a properly-formatted commit message. This kept development velocity high without sacrificing consistency.
